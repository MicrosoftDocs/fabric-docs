# Mirrored AWS Glue catalog

A mirrored AWS Glue catalog in Fabric integrates the data cataloged in your AWS Glue Data Catalog with the rest of your data in Fabric. You can continuously mirror your AWS Glue catalog structure directly into Fabric's OneLake.

For a tutorial on configuring your AWS environment for AWS Glue catalog mirroring into Fabric, see [Tutorial: Configure mirrored AWS Glue catalog](aws-glue-tutorial.md).

[!INCLUDE [feature-preview-note](../../includes/feature-preview-note.md)]

When you mirror an AWS Glue catalog, there's no data movement or duplication. Only the AWS Glue catalog structure is mirrored to Fabric, and the underlying Iceberg table data stays in Amazon S3 and is accessed through shortcuts. Changes to the underlying data might not appear in Fabric immediately. Propagation can take anywhere from a few seconds to several minutes, as described in the [SQL analytics endpoint performance documentation](../../data-engineering/sql-analytics-endpoint-performance.md).

## What analytics experiences are built in

Mirrored catalogs are items in Fabric distinct from other items such as lakehouses and SQL analytics endpoints.

When you mirror an AWS Glue catalog, Fabric creates these items:

- Mirrored AWS Glue catalog item
- A [SQL analytics endpoint](../../data-engineering/lakehouse-sql-analytics-endpoint.md) for this item

You can access your mirrored AWS Glue catalog data multiple ways:

- Use T-SQL commands to define and query data objects from the read-only SQL analytics endpoint. Each mirrored AWS Glue catalog item has an autogenerated SQL analytics endpoint that provides a rich analytical experience created by the mirroring process.
- Use Power BI with Direct Lake mode to create reports against the mirrored AWS Glue catalog item.
- Use other Fabric workloads to query tables in the mirrored AWS Glue catalog item.

Mirrored tables are available to query within seconds after selection, with end-to-end metadata propagation typically completing in seconds to a few minutes.

## Connect and authenticate

Mirroring connects to the [AWS Glue Iceberg REST catalog](https://docs.aws.amazon.com/glue/latest/dg/connect-glu-iceberg-rest.html) endpoint for your AWS account. The underlying table data stays in Amazon S3 and is read through shortcuts, so the connection needs permissions to both the AWS Glue Data Catalog and the Amazon S3 locations that store the Iceberg data.

AWS Glue catalog mirroring uses a delegated authorization model. In this model, the person who creates the connection provides an AWS Identity and Access Management (IAM) credential, and all mirroring access is authorized by using that credential. The following authentication kind is supported:

- **Key** – Authenticate by using the access key ID and secret access key of an AWS IAM user. Fabric stores the credential with the connection and uses it for the initial catalog scan and for ongoing metadata sync.

The IAM identity that you use for the connection must have read access to the AWS Glue Data Catalog and to the Amazon S3 data:

| Service | Permissions |
|---------|-------------|
| AWS Glue | `glue:GetCatalog`, `glue:GetDatabases`, `glue:GetDatabase`, `glue:GetTables`, and `glue:GetTable` |
| Amazon S3 | `s3:GetObject`, `s3:GetBucketLocation`, and `s3:ListBucket` on the buckets that store the Iceberg table data |

If [AWS Lake Formation](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) governs your AWS Glue Data Catalog, grant the same IAM identity the corresponding Lake Formation permissions on the databases and tables that you want to mirror. Otherwise, those databases and tables don't appear when you select data to mirror.

For step-by-step instructions to configure the IAM credential and the connection, see [Tutorial: Configure mirrored AWS Glue catalog](aws-glue-tutorial.md).

## Metadata sync

When you create a new mirrored AWS Glue catalog in Fabric, the **Automatically sync future tables** option is enabled by default. If you enable automatic sync, Fabric reflects the following metadata changes from your AWS Glue Data Catalog:

- Addition of databases to the catalog
- Deletion of databases from the catalog
- Addition of tables to a database
- Deletion of tables from a database
- When **Automatically sync future tables** is enabled, newly created Iceberg tables in selected databases are automatically included in Fabric without requiring a manual refresh.
- Schema and data changes to existing tables follow normal propagation intervals.

Schema and table selection:

- You can select which AWS Glue databases to include as schemas, and you can exclude certain tables.
- Unselecting a database unselects all the tables within the database.
- If you go back and select the database, all tables within the database are selected again.
